# 代码审查 Skill

## 1. 摸清现场
- 单文件：`read_file` 完整读取；
- 多文件项目：先 `list_dir` 摸清结构，再读入口与相关模块；不基于猜测点评。

## 2. 审查维度（按优先级）
1. **正确性**：边界条件、异常路径、资源泄漏、并发问题；
2. **安全**：注入、路径穿越、硬编码密钥、不安全反序列化；
3. **可读性**：命名、函数长度、重复代码、魔法数字；
4. **性能**：只在有证据时谈性能（复杂度分析或实测），不过早优化。

## 3. 输出报告
- 按严重度分级：`[阻塞]` 必须修 / `[建议]` 应该修 / `[风格]` 可选；
- 每条给出：`文件:位置`、问题描述、具体修复建议（可给示例代码片段）；
- 结论回答："这份代码能不能安全地用于生产/提交"。

## 4. 修复（仅在用户同意后）
- 用 `edit_file` 小步修改，每步 `run_command` 验证不回归；
- 重构前先确保有验证手段（测试/脚本），行为必须保持不变。
