# 调试排错 Skill

修复任何 bug 都走这条链路：

## 1. 复现
- 先用 `run_command` 运行出问题的命令/代码，拿到**完整**报错输出（不猜、不省略）；
- 复现不了就让用户提供触发条件（输入/环境/版本）。

## 2. 定位
- 读 traceback：从最底层属于自己的代码帧开始看，不要只看最后一行；
- 缩小范围：二分注释、加最小日志（print/logging）、构造最小复现脚本。

## 3. 修复
- 一次只改一个变量；每个假设都先用工具验证再下结论；
- 修根因，不打绕过式补丁；**禁止用 try/except 吞异常当作修复**；
- 用 `edit_file` 小步修改，不整文件重写。

## 4. 验证
- 回归验证：原报错场景必须重跑通过；
- 相邻场景：至少再跑一个可能被改动影响的用例。

## 5. 交付
最终答复按顺序给出：根因 → 修复内容（文件与改动点）→ 验证结果 → 以后如何避免。
